# `git.io/v2ray.sh` 设计参考

本文记录对 [`https://git.io/v2ray.sh`](https://git.io/v2ray.sh) 的设计审阅。该短链在
2026-09-29 指向 233boy/v2ray 的 `install.sh`。这里只总结可复用的工程思路，不复制代码，
也不表示两个项目的配置、内核或安全边界相同。

## 值得借鉴的优点

| 优点 | 脚本中的表现 | 对使用者的价值 |
| --- | --- | --- |
| 安装前置检查集中 | 启动时检查 root、包管理器、systemd 和 CPU 架构 | 失败发生在写入系统之前，报错位置清楚 |
| 多种安装输入 | 支持指定 Core 版本、本地安装包、本地脚本目录和下载代理 | 兼顾固定版本、弱网络、镜像和离线部署 |
| 架构自动选择 | 区分 x86_64 与 ARM64，自动选择 Core 和 jq 包 | 同一入口覆盖常见 VPS 与 ARM 服务器 |
| 准备工作并行 | 依赖安装、Core、管理脚本、jq 下载和公网 IP 查询并行执行，随后统一 `wait` | 网络较慢时可以缩短首次安装等待时间 |
| 状态汇总 | 每项准备工作有独立完成标记，集中判断失败并给出补救提示 | 避免前一步静默失败后继续生成半成品安装 |
| 参数约束明确 | `--help` 列出参数，并拒绝同时指定 Core 版本和本地 Core 包 | 减少含糊输入和不可预测的优先级 |
| 本地包预检 | 解压自定义 Core 包并确认二进制、`geoip.dat`、`geosite.dat` 存在 | 在覆盖系统文件前发现损坏或错误架构的压缩包 |
| 模块职责分离 | 安装入口加载独立的 systemd 和 Core 配置模块 | 便于维护协议配置和服务定义 |
| 重复安装保护 | 检测已有目录和命令后停止，提示使用专门的重装命令 | 降低误覆盖正在运行节点的概率 |
| 操作反馈友好 | 彩色、带时间的安装状态与明确的成功/失败提示 | 新用户能看出脚本当前在做什么 |
| 时间同步提醒 | 尝试启用 NTP，失败时说明可能影响对时间敏感的协议 | 把常见环境问题提前暴露给操作者 |

## 当前项目已经吸收或强化的部分

- `v2ray-manager` 同样执行 root、systemd、发行版和 x86_64/ARM64 检查；支持通过完整
  Git 提交固定管理脚本版本。
- Core 下载进入真实的 `mktemp -d` 暂存目录，并验证官方 `.dgst` 中的 SHA-256；候选
  Core 还必须通过现有 Xray 配置检查，之后才会替换运行文件。
- 更新和配置变更均先备份，采用同目录临时文件与重命名安装；启动或健康检查失败时
  自动回滚。原本停止的服务不会被更新流程意外启动。
- 安装状态进一步扩展为 `v2ray doctor`：检查配置、服务、全部监听端口、REALITY 目标
  DNS/TLS 1.3，以及导出参数和实际入站的一致性。
- 管理器保留单文件发布物，避免服务器运行时依赖一组可能只下载了一部分的模块；仓库
  中仍用 `tests/`、`tools/`、`templates/` 和 `config/` 分离维护职责。
- GitHub Actions 运行 ShellCheck、单元与恢复测试，并用实际稳定版 Xray 检查全部服务端、
  客户端和多入站配置。

## 后续可以继续吸收的方向

1. 为安装器增加显式下载代理参数，并确保代理值不会写入日志或永久环境。
2. 增加经过摘要验证的本地 Core 压缩包入口，服务于离线和受限网络部署。
3. 在不牺牲可诊断性的前提下，并行下载相互独立的 Core、GeoData 和校验文件。
4. 将 NTP 状态加入 `doctor` 的只读检查；不自动更改运营者的时间服务方案。
5. 保持简洁的命令帮助和分阶段状态输出，进一步统一交互安装与非交互安装的错误信息。

这些项目是设计候选，不代表当前版本已经支持。实现时仍需遵循本项目现有的固定提交、
摘要校验、原子替换、服务健康观察和失败回滚要求。

## 不应照搬的实现

原脚本形成较早，以下写法不适合当前项目的安全标准：

- `wget --no-check-certificate` 会绕过 HTTPS 证书验证。本项目必须保留正常 TLS 验证，
  并继续校验 Xray 发布摘要。
- `mktemp -u` 只生成名称而不安全创建目录，存在竞争窗口；本项目使用真实创建的临时文件
  或目录，并用退出陷阱清理。
- 多处路径和参数未加引号，遇到空格、通配符或异常输入时可能拆词；新增代码必须通过
  ShellCheck 并正确使用数组和引用。
- 下载成功主要通过标记文件判断，未对所有下载物做密码学完整性校验；本项目不能降低
  已有的 SHA-256 和候选配置验证。
- 直接复制、移动到最终目录缺少完整事务回滚；本项目继续使用备份、暂存验证、健康观察
  和失败恢复。
- 自动修改 NTP、shell alias 或系统包属于有持续影响的系统变更。除安装必需依赖外，
  应先诊断并在文档中说明，而不是把偏好当成通用默认值。

## 结论

该脚本最值得学习的是安装体验和输入覆盖面：把前置条件、架构、下载来源、进度反馈、
本地包检查和失败汇总组织成清晰流程。当前项目在完整性校验、原子更新、回滚、低权限运行
和配置真实性检查上要求更高，因此应吸收其交互与部署思路，同时保留现有安全边界。
